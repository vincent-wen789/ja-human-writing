# ja-human-writing

日本語が「人の書いた文章」として読めるようにする Claude Code スキル。

v0.1.0 · 2026-08

## まず、直したいのはこういう文章

```
近年、デジタル資産の世界は急速な発展を遂げています。しかし、その一方で、
セキュリティに関する課題も浮き彫りになってきていると言えるでしょう。
```

## 目指すのはこういう文章

```
7月7日、Gate のあるユーザーの口座から170万ドルが41分で抜かれた。
気づいたのは26時間後。
```

違いは語彙ではない。上の文には日付も金額も無く、誰も何もしていない(「課題が浮き彫りになる」の主語は課題だ)。書き手がその件を実際には見ていない、ということが読めてしまう。

**禁止語を消しても、上の文は下の文にならない。** 足りないのは素材と、語る人の位置。ここを埋めるのがこのスキル。

## これは何で、何ではないか

**文章を解析するプログラムではない。Claude への指示と手順をまとめたもの。** 検出のプログラムは自作せず、既にあるものに投げている。

- 機械で測れる部分(文の長さのばらつき、禁止語、翻訳調)→ [coji/natural-japanese](https://github.com/coji/natural-japanese) の lint(機械チェッカー)に投げる
- 禁止語の語彙リスト → [stop-ai-slop-jp](https://github.com/iKora128/stop-ai-slop-jp) と [slop-nuki](https://github.com/chezou/slop-nuki) から輸入して再構成した。**中身は重複する**(詳しくは「既存スキルとの関係」)
- **このスキル自身の実体は3つ** —— ①書く前の素材ゲート ②「語りの位置」の設定 ③機械の指摘を鵜呑みにせず「これは書き手の声か」を1件ずつ判定させるループ

## 三つの部品

**1. 書く前のゲート**

1200字を超えるノンフィクションは、出どころ付きの具体的な素材を5件そろえてから書き始める。日付・金額・固有名詞・実際の発言・失敗したこと。5件出なければ、調べるか、正直に短く書く。素材の無い長文は、どれだけ推敲しても水増しのままだから。

**2. 三つの「逆方向」注意**

AI臭を消す定番の直し方が、実測では逆に効く。下の節。

**3. 検出と判定を分ける**

機械が「疑い」を出し、**Claude がスキルの規則に照らして1件ずつ「直す/残す」を判定する。** あなたが日本語の自然さを自分で判定する必要はない(最終的に採否を決めるのはあなただが、探すのは機械と Claude の仕事)。

## 定番の直し方3つが、実測では逆だった

| よく聞く直し方 | 実測 | 正しい向き |
|---|---|---|
| 繰り返しを類義語に置き換える | 語彙の多様性(TTR = 使われた語の種類 ÷ 総語数)は **AI の方が高い**。繰り返すのは人間の側 | 置換しない。繰り返しを許す |
| 無機質だから比喩を足す | 比喩は **AI の方が数倍多い**。「まるで〜のよう」は AI 頻出 | 足さない。テンプレ比喩を削る |
| 接続詞が多いから削る | 硬い文体では**使用量にほぼ差が無い**。差は種類で、AI は「一方/しかし/また」に偏る | 量を減らさず、種類を替える |

### 根拠の強さ(そのまま書いておく)

この3つは**強さの違う2つの出典**に立っている。

- **査読論文**:Zaitsu &amp; Jin 2023, *PLoS One* 18(8), [PMID 37556434](https://pubmed.ncbi.nlm.nih.gov/37556434/) —— 機能語(「は」「が」「ので」のような、内容ではなく文の骨格をつくる語)の使用率などから日本語のAI生成文を判別。リンクから誰でも今すぐ確認できる
- **学部の卒業論文**:大西夢『AI生成文からみた「自然な日本語」についての研究』(広島大学文学部 2026)—— AI・人間各20篇の比較。**サンプル20篇の学部卒論で、外部からの検証は容易ではない**

上の表の「AI の方が高い/多い」という**向き**は卒論の観察による。**具体的な数値は閾値として使っていないので、ここには載せない**(スキル内部でも判定に使っているのは向きだけ)。数字が知りたい場合は `references/evidence-ja.md` に出典付きで書いてあるが、**方向の参考であって普遍的な閾値ではない**、という但し書き込みで読んでほしい。

この卒論でいちばん使えたのは数値ではなく枠組みの方だった。AIらしさを二層に分ける——読者が指させる特徴(特定の語彙、読点の位置)と、指させないのに感じ取っている特徴(文の長さのばらつき、断定を避ける密度)。**差が出たのは、ほぼ後者だった。**

## インストール

**前提**:[Claude Code](https://claude.com/claude-code) が動く環境。ターミナルを一度だけ使う。追加の課金は不要(Claude の利用枠の中で動く)。

ターミナルを開いて、この3行を上から順に貼る。

```bash
mkdir -p ~/.claude/skills
git clone https://github.com/vincent-wen789/ja-human-writing.git
cp -R ja-human-writing/ja-human-writing ~/.claude/skills/
```

機械チェッカーも入れるなら(任意・推奨)、続けてこの2行。

```bash
git clone https://github.com/coji/natural-japanese.git
cp -R natural-japanese/skills/natural-japanese ~/.claude/skills/
```

以降ターミナルは使わない。

## 使う

Claude Code に話しかけるだけ。

```
あなた:  この note の下書き、AI臭を消して

Claude:  機械チェックで7件。うち3件を直します。

         L3 「〜と言えるでしょう」→ 言い切りに変えました
         L9 段落の長さが全部同じ → 1段落を2文に切りました
         L21 この段落、固有名詞も数字もありません。
             実際の店名か日付は入りますか?

         残り4件は直していません。「〜と思う」の繰り返しは、
         あなたの語り口として機能しているので残します。
```

他にもこんな頼み方をする。

- **「○○について note 記事を書いて」** —— 素材ゲートが先に走る。素材が足りなければ、空の原稿を出す前に質問が返ってくる(質問は一度にまとめて最大3つ。それ以上は往復させない)
- **「このメールの敬語を見て」** —— 二重敬語、「させていただく」の濫用、クッション言葉の連打

## 自分の文体を学ばせる(任意)

「規則に従わせたら、自分の書き癖まで消されるのでは」——ここは設計で守っている。

自分が納得している過去原稿を1〜3本渡すと、文の長さのリズム・判断の下し方・敬体の締め具合を下敷きにする。そして**複数の文章をまたいで繰り返し出てくる癖は、禁止表に載っていても削らない。** 一篇の中では揺れて、篇をまたぐと一貫している——それが人間の文体で、AI はちょうど逆(一篇の中が均一で、篇をまたぐと無個性)だから、その癖こそ守る対象になる。

## 既存スキルとの関係

**禁止表の語彙は stop-ai-slop-jp と slop-nuki から輸入して再構成したもので、中身は重複する。** ここは隠さずに書いておく。

その上での差分は2つ。**書く前の層**(素材ゲート、語りの位置)を持っていること。そして**直す向き**——上の「三つの逆方向」を守らないと、消臭したつもりで AI 方向へ寄せてしまう。

3つ全部入れる場合:natural-japanese は lint として呼ばれるだけなので競合しない。stop-ai-slop-jp と本スキルは**禁止語彙が二重にロードされる**(内容が近いので矛盾はしないが、コンテキストは食う)。**どちらか一方で足りる。** すでに stop-ai-slop-jp を使い込んでいて、書く前の層に興味が無いなら、乗り換える理由は薄い。

**コンテキストの実測**:常時載っているのは description の数十トークンだけ。スキルが起動したとき `SKILL.md` 本体で**約1万トークン**(概算)、`references/` は必要になったときだけ読む(禁止表 約7.7k / 実証層 約3.9k)。スキルを10個以上入れている環境なら、この数字で判断してほしい。

## 限界

- **実測の土台は意見文と作文の比較で、SNS の短文は入っていない。** 140〜500字では文の長さの統計がサンプル不足で沈黙する
  - **短文で何が効くか**:定型句(「いかがでしたか」等)、翻訳調、主語のすり替え、記号の残骸、素材の有無——ここは文字数に関係なく効く
  - **短文で効かないもの**:文長のばらつき、段落構成、体言止めの比率。スキルはこれらを「適用外」と明示して黙らせる
  - **黙ったことを「AI臭なし」と読まない。** そこだけは自分の目で読む
- **土台は意見文・エッセイ・取材もの。技術記事は想定の中心ではない。** 素材ゲートが求める「日付・金額・実際の発言・失敗したこと」は、体験や取材が入る文章には効くが、技術解説だと素材の形が違う(コード・エラーメッセージ・バージョン・再現手順)。禁止表と文体の部分はそのまま効くので、技術記事なら lint を `--genre tech` で回して、素材ゲートは参考程度に見るのが現実的
- 根拠の一方は学部の卒業論文(サンプル20篇)。上に書いた通り、数値ではなく向きだけを使っている
- **検証は1件のみ**(`examples/`)。手順が再現できることの確認であって、効果の証明ではない
- バージョン 0.1.0。上流(natural-japanese、stop-ai-slop-jp)が更新されたときの追従は手動。気づいたことは Issue に投げてもらえると助かる
- 作者は日本在住のマーケター([@vinentW789](https://x.com/vinentW789))で、エンジニアではない。日本語で書いて出す側の必要から作ったもので、自分が使い続ける限りは直す。企業のバックアップは無い

## 構成

| ファイル | 中身 |
|---|---|
| `SKILL.md` | 本体。文書タイプの判定 → 素材ゲート → 語りの位置 → 執筆の規律13条 → 納品前の禁止表 → 検査のループ |
| `references/forbidden-ja.md` | 禁止パターン集(定型句/AIが好む語/大げさな語彙/主語のすり替え/構造/敬語/漢語の硬さ/記号) |
| `references/evidence-ja.md` | 実証層。二層の枠組み、人間らしさの三要素、指標、三つの逆方向 |
| `examples/` | before/after の実テキストと lint 結果。自分の手で再現できる |
