# ja-human-writing

読み手に具体的な書き手の判断が伝わる日本語を書く。人間らしさは素材、語りの位置、語り口から来る。「なんすよ」や(笑)を足したり、体験を作ったりして演出しない。

## 最初に、執筆と軽い改稿を分ける

- **素材からの執筆**：構成を組み、確認済みの情報を補える。書き手の体験・発言・立場は創作しない。
- **成稿のAI臭除去・軽い推敲**：必要な箇所だけ直す。構成、事実、主張、引用、否定、条件、数値、確信の度合いを保つ。すでに自然な文は残す。全面改稿や再構成は依頼されたときに行う。
- 修正には「指す対象が不明」「同じ内容の繰り返し」「文体に合わない言い回し」など具体的な理由が要る。語彙表への命中や文長の均一さだけでは直さない。迷ったら残す。
- 「可能性がある」を言い切りに変えず、確認済みの事実を「らしい」に弱めない。直接引用は改変しない。言い換えるなら引用から外して要約と分かる形にする。

**優先順位：依頼内容と情報の正確さ > 書き手の声・レジスタ・読みやすさ > 個別の候補ルール > lint の統計。** 参考ファイルにもこの境界を適用する。

## 守備範囲

| 層 | 担当 |
|---|---|
| 素材・語りの位置・執筆・改稿 | 本スキル |
| 機械検査 | 任意の [coji/natural-japanese](https://github.com/coji/natural-japanese)。未導入なら §6 の手動確認 |
| テーマ選定・読者設定 | 依頼や上流の企画に従う |

表現に迷うときだけ [references/forbidden-ja.md](references/forbidden-ja.md) を読む。統計の根拠や適用範囲は [references/evidence-ja.md](references/evidence-ja.md)。毎回すべて読み込まない。

## 0. レジスタを決める

1. **SNS短文（140〜500字）**：下の短文プロファイル。lint は `--genre essay`。
2. **note・ブログ・個人の文章**：素材と語りの位置を確認。lint は `--genre essay`。
3. **ビジネスメール・文書**：natural-japanese があればそちらを主に使う。本スキルからは参考表 §6 の敬語チェックを必要に応じて足す。§3 の個人向け執筆規律は適用しない。lint は `--genre business`。
4. **技術記事・技術文書**：情報の並びと再現可能性を優先。素材はコード、エラー、バージョン、再現手順。§3 を適用せず、一人称や体験談を強制しない。lint は `--genre tech`。

### 短文プロファイル

| 観点 | 長文 | SNS短文 |
|---|---|---|
| 素材 | 論旨を支えられるか確認 | 具体的な手掛かりを確認。件数を課さない |
| 文長・段落長 | 読みづらさを探す補助 | 極短文を要求しない |
| 体言止め | 固定比率を課さない | 断片文を認めるが足す義務はない |
| 定型の締め | 空疎・重複なら整理 | 実際の質問や誘いは残す |
| さて／それでは | 文脈で判断 | スレッドの転換として使える |
| 反転構文 | 架空の誤解を立てていないか | 同左。実際の訂正は残す |
| 一人称・絵文字・業界語 | 書き手の語り口と読者に合わせる | 人間らしさのために追加・削除しない |

統計検出器にはそれぞれ長さの条件がある。未評価は「適用外」と読み、表層の指摘も文脈で確認する。指摘がなくても自然さの証明にはならない。

## 1. 素材を確かめる

新規のノンフィクションや依頼された加筆では、具体的な素材と出どころを整理する。動作、数字、日時、場所、発言、失敗、代償、結果が素材になる。隣り合う正論や同じ話の言い換えは別の素材に数えない。

1200字を超える稿では5件程度を点検の目安にするが、品質の閾値ではない。一つの十分な経験や事例でも長文を支えられる。軽い改稿では、素材が少ないという理由だけで検索・加筆・短縮しない。

- 論旨を支えられなければ依頼の範囲で調べる。本人の体験が必要なら要点をまとめて質問する。それでも足りなければ不足を伝えてテーマの絞り込みを提案する。指定の長さを勝手に変えたり、例を作って水増ししたりしない。
- 出典のない「ある調査によると」「多くの専門家が」で事実を装わない。書き手の体験として使えるのは、本人から提供されたものだけ。
- フィクションでは、場面を支える人物の目的・行動・変化を確認する。

## 2. 語りの位置

書く前に内部で確認する。読者向けの説明は不要。

1. 誰が語り、何を知っていて、どこからが推測か。
2. なぜ今この話をするのか。
3. どの素材が判断を支えるか。
4. 書き手の判断はどこにあり、その根拠と限界は何か。
5. 読者が次に知りたいことは何か。

意見稿なら判断を明確にする。説明の段落にまで個人的な立場を足さない。「自分は」の回数で書き手の存在を示そうとしない。

## 3. 執筆の規律

1. **出来事から入る。** 事実、場面、具体的な問いを書く。空疎な時代説明や架空の読者像による反転は避ける。必要な背景は残す。
2. **行為者と指示対象を明確にする。** 「データが示している」はそのまま使える。文脈から分かる主語も補わなくてよい。必要な補足は素材の範囲で行い、行為者を作らない。
3. **一般化の範囲を守る。** 「多くの人」「誰もが」には根拠が要る。個人の経験を全体の事実に広げず、一般論を架空の実体験に変えない。
4. **判断には根拠と限界を添える。** 「悪くない」「微妙」も正当な判断。勢いのために断定を強めず、保険のために弱めない。
5. **事実と伝聞を分ける。** 確認済みの公開情報は出典付きで直接書ける。「らしい」「ようだ」を機械的に足さない。「と聞いた」は実際に聞いた話にだけ使う。
6. **素材で支える。** 抽象的な段落で、どの事実や経験が主張を支えているか確かめる。固有名詞や数字を飾りとして追加しない。
7. **リズムは内容に合わせる。** 大事な点は展開し、軽い点は短くする。読みづらい反復があるときだけ文を調整し、統計を変えるために極短文や長文を作らない。
8. **文末は意味と声に合わせる。** 敬体が続いてもよい。願望・疑問・体言止め・終助詞は必要なときに使い、配分を決めない。
9. **読点で理解を助ける。** 音読と修飾関係を見て調整する。文ごとの個数で増減しない。
10. **段落で話を進める。** 事実、例、区別、帰結を積む。同じ主張の言い換えを水増しに使わない。
11. **背景は必要な場所で出す。** 判断や理解に役立つ説明を、その問いが生じる場所に置く。
12. **感想を無理に格上げしない。** 「大浴場気持ちよかった、よく寝れた」で十分なら、回復や人生の教訓を追記しない。
13. **話が終わったら止める。** 重複する要約や素材を超えた未来論を足さない。実際の質問、誘い、必要なまとめは残す。

## 4. 成稿の確認

以下は修正候補。回数や字面だけで違反としない。参考表の具体例も自動置換には使わない。

| 候補 | 判断と修正の範囲 |
|---|---|
| 対応の取れない Markdown、意図しない空白 | 書式エラーを確認して直す。コード・リンク・引用・正当な記号は保つ |
| いかがでしたか／ぜひ〜してみてください 等 | 空疎な定型や重複か確認。質問・誘い・案内として働くなら残す |
| AではなくB 等 | 架空の誤解や反転の連発を確認。実際の訂正や比較、Aへの否定は保つ |
| 3つのポイント 等 | 数合わせの重複か確認。独立した3項目や必要な番号はそのまま |
| 壮大な語彙、横文字メタファー | 素材以上に大きく言っていないか。説明に役立つ比喩や専門用語は残す |
| 可能性がある／とは限らない 等 | 同じ限定の重複だけ整理。異なる条件はそれぞれ残し、段落ごとの上限を課さない |
| 見出しと冒頭文の言い換え | 情報のない繰り返しだけ整理。判断を伝える見出しは残す |
| 節ごとの免責・留保 | 同じ説明ならまとめる。異なる対象やリスクへの限定は残す |
| 敬体と常体の切り替え | 意図しない混交を直す。引用・内心の声・作者の意図は尊重する |
| 抽象漢語の連続 | 関係を取りにくい場合だけほどく。術語や正式文書の表現を無理に口語化しない |

## 5. 機械的にしない修正

1. **多様性のために類義語へ置換しない。** 用語や話題語は繰り返せる。冗長なら文ごと直し、意味のずれを防ぐ。
2. **人間らしさのために比喩を増減しない。** 理解、声、面白さを支える比喩は残す。空疎な格上げや重複だけ整理する。
3. **種類を増やすために接続詞を替えない。** 「しかし」「また」「だから」は論理が異なる。対比・追加・因果を保つ。

これらは編集上の判断で、普遍的な人間／AIの分類規則ではない。研究の条件は references/evidence-ja.md を参照。

## 6. 検査工程

natural-japanese がインストールされていれば lint を使う。以下は実行例。`ja_draft` を実際の原稿パスに、`ja_genre` を §0 の文書タイプに置き換える。

```bash
ja_draft="/absolute/path/draft.md"
ja_genre="essay"
ja_lint_script=""
for ja_skill_dir in "${CODEX_HOME:-$HOME/.codex}/skills/natural-japanese" "$HOME/.agents/skills/natural-japanese" "$HOME/.claude/skills/natural-japanese"; do
  if [ -f "$ja_skill_dir/scripts/lint.py" ]; then
    ja_lint_script="$ja_skill_dir/scripts/lint.py"
    break
  fi
done
if [ -n "$ja_lint_script" ] && command -v uv >/dev/null 2>&1; then
  ja_lint_dir=$(mktemp -d "${TMPDIR:-/tmp}/ja-writing-lint.XXXXXX")
  uv run "$ja_lint_script" --json "$ja_draft" --genre "$ja_genre" > "$ja_lint_dir/r1.json"
fi
```

- コマンドが正常終了し、有効な JSON が得られたことを確認する。失敗・未導入・`uv` 不在は手動確認へ進み、「機械検査未実施」と伝える。空の結果を合格扱いしない。
- **手動確認**：意味と条件が保たれたか、指示対象が分かるか、重複があるか、語り口が文書に合うかを読む。natural-japanese の `references/manual-checklist.md` があれば併用できるが、必須依存ではない。
- **各 finding を判断**：書き手の声やレジスタ上必要な表現なら残す。具体的な読みにくさがあるときだけ直す。`low_burstiness`、語彙多様性、文長・段落長、体言止めなどの統計は直接の修正命令にしない。
- **全体を確認**：情報のない前置き、反転、教訓が反復していないか。必要な対照、並列、意図した反復は保つ。
- **改稿した場合**、初回の lint が成功していれば同じ文書タイプで再実行する。新しい指摘だけ再判断し、ゼロ件を目標にしない。

```bash
uv run "$ja_lint_script" --json "$ja_draft" --genre "$ja_genre" --baseline "$ja_lint_dir/r1.json" > "$ja_lint_dir/r2.json"
```

最後にルールを離れて通読する。事実、引用、否定、条件、語気が変わっていないか。どこに書き手の判断があり、読者がつまずく箇所はどこか。

## 7. 文体キャリブレーション（任意）

ユーザーが認める過去原稿を1〜3本受け取ったら、判断の下し方、語彙、敬体の締め具合などを参考にする。個人の癖は語彙表への命中だけで削らない。文体を統計的な人間らしさへ揃えない。

## 8. 納品

既定では作品を渡す。変更理由を求められたら具体的に説明する。素材リストや内部の判断記録は通常見せない。片付けるのは今回の一時ディレクトリ内に自分で作った不要なファイルだけ。ユーザーの原稿、既存の JSON、中間版は消さない。著者プロファイルを勝手に作らない。
