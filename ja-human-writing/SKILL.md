# ja-human-writing

読み手に「対面に具体的な人がいる」と感じさせる日本語を書くためのスキル。その人はこの件を実際に見ていて、自分の判断を持っていて、細部を語る気がある。たまに脱線して、また話を戻す。

人間らしさは第一に素材から、第二に語りの位置から、最後に語り口から来る。「なんすよ」や(笑)を足して偽装するものではない。

## 守備範囲(他のツールとの分担)

| 層 | 担当 |
|---|---|
| 書く前の規律 + 納品前の禁止事項 | **本スキル** |
| 機械検査(形態素解析 lint) | [coji/natural-japanese](https://github.com/coji/natural-japanese) — 任意の併用スキル。インストール済みなら委託、無ければ §6 の手動降格 |
| テーマ選定・読者設定 | 本スキルの外。ここは「書き上がった日本語が人に読めるか」だけを見る |

ビジネス文書(議事録・レポート・社内ガイド)は natural-japanese の全工程に任せてよい。本スキルはその場合、§4 の敬語チェックだけ足す。SNS・note・個人の文章・マーケ文は本スキルが主。

## 0. レジスタ判定(30秒で決める)

1. **SNS 短文(140〜500字)** → 本文 + 下の短文プロファイル。lint は `--genre essay`
2. **note・ブログ長文** → 本文 + 素材ゲート全量。lint は `--genre essay`
3. **ビジネスメール・文書** → natural-japanese 主導 + `references/forbidden-ja.md` §6 の敬語表。lint は `--genre business`。敬語の「残すもの」表が削除より優先。この場合、§3 の一人称ルールは「主体を明示する」(弊社/当方/担当の○○)に読み替える
4. **技術記事・技術文書** → 本文 + `references/forbidden-ja.md`。lint は `--genre tech`。**素材ゲート(§1)は参考程度に落とす**——技術文の素材はコード・エラーメッセージ・バージョン・再現手順で、日付や発言とは形が違う。禁止表・文体・リズムの部分はそのまま効く

**衝突の裁決順:レジスタ適合 > 密度 > 個別の禁止。** 個別ルールがレジスタの慣習とぶつかったらレジスタが勝つ。ビジネスの敬語、業界の口語、スレッドの転換句は slop ではない。

### 短文プロファイル(SNS 用)

長文向けの統計は短文では失効するか、逆に人間らしい書き方を誤射する。

| ルール | 長文 | SNS 短文 |
|---|---|---|
| 素材ゲート5件 | 必須 | 省略。具体的なアンカー(数字・固有名詞・実体験)1つで可 |
| 文長・段落のばらつき | 主指標 | 「極端に短い一文があるか」だけ見る |
| 体言止め 20% 上限 | 有効 | 解除(短文の断片文は正当) |
| 定型の締め(いかがでしたか系) | 禁止 | 禁止(維持) |
| さて/それでは | 弱シグナル | **免除**(スレッド転換の慣習) |
| 絵文字 | 均等撒布のみ削除 | 同左(界隈の記号は正当。🚀連発だけが slop) |
| 反転構文(AではなくB) | 3回以上で構造的 slop | **1回で疑う**(短文では1回で臭う) |
| 一人称 | 推奨 | 推奨(SNS の人間らしさの本体) |

短文に lint をかけるときの注意:統計系検出器はサンプル不足で**沈黙する**(5文未満・約1500字未満・約4000字未満でそれぞれ止まる項目がある)。短文では表層の finding(定型句・翻訳調)だけを信じ、統計項は「適用外」。**沈黙は「AI臭なし」ではない。**

## 1. 素材ゲート(ノンフィクション長文は必ず通す)

**1200字を超えるノンフィクションを書く前に、具体的な素材を最低5件、出どころ付きで内部に書き出す。** 素材とは動作・数字・日時・場所・発言の原文・失敗・代償・結果。隣り合う5つの正論は素材ではない。

- 5件出ない → 調べられるものは先に調べる(検索できるのにしないのは素材ゼロと同じ)。ユーザーの体験に頼る文章なら、質問は一度に3つまで。それでも足りなければテーマを絞り、600字前後の短い稿で納める。**水増しするくらいなら短く。**
- 偽素材の赤線:出典のない「ある調査によると」「多くの専門家が」「〜と言われています」。出どころを言えないデータに段落を支えさせない。
- フィクションはこのゲートを通さない。代わりに各場面を誰の目的・行動・変化が支えているかを確認する。

## 2. 語りの位置(書く前に内部で答える。読者には見せない)

1. 誰がこれを語るのか。何を根拠に知っていて、どこからが推測か。
2. なぜ今これを言うのか(ニュース・体験・ずっと引っかかっていたこと)。
3. 文章を支える手持ちは何か(動作・数字・原文・失敗・代償)。
4. どこに自分の判断があるか。根拠は何で、どこまでか。
5. 前の段落を読んだ読者が、次に自然に何を訊くか。

3が薄ければ素材ゲートに戻る。4が答えられないなら、それは記事ではなく百科事典の項目になる。**AI臭の正体は、書き手の不在**(stop-ai-slop-jp の大原則)。

## 3. 執筆の規律(書きながら守る。書いた後の照合表ではない)

1. **冒頭で出来事に触れる。** 事実・場面・妙な小さい事実から入る。「近年〜が注目されています」の大上段も、「〜な人は多いはずだ。しかし」の英語ブログ型フックも書かない。人間は控えめから確信へ進む。AI は断言から退縮する。
2. **主体を立てる。** 無生物に人間の動詞をさせない。「データが示している」→「データを見るとこうなっている」。「誰が」が書けないなら具体性が足りない。
3. **一人称で引き受ける。** 「多くの人」「人々は」ではなく「自分は」。自分の小さい話を人類の命題に格上げしない。
4. **判断を下す。根拠と限界を添える。** 中間温度は正当:「悪くない」「まあまあ」「微妙」「よく分からんけど好き」。全部「最高」も全部ぼかしも機械の癖。
5. **調べた事実には伝聞を混ぜる**:「らしい」「そうだ」「ようだ」。言い切るのは自分で確かめたことだけ。全断定も全ぼかしも不自然で、比率の問題。
6. **固有名詞と数字で着地する。** 実測では、AI は「旅の思い出」を固有名詞ゼロで書き通すことがある。抽象的な段落で手を止めて、金額・日時・人名・地名がどこにあるか確認する。
7. **ばらつきが人間らしさの統計的本体**(詳細は `references/evidence-ja.md`)。極端に長い文と極端に短い文の両方を持つ。厚い節と、正直に薄い節。全文が5〜15文節の等速で並んだら、単語をいくら直しても機械に読める。
8. **文末を揃えない。** です・ます が3文続いたら単調(長文の場合。SNS の3文は普通)。「〜たい」「〜と思う」「〜か?」は実測で人間専用に近い文末。体言止めは人間らしさの道具(実測:人 21 回 vs AI 6 回)で、使ってよいが毎段落は打たない。口語の終助詞(ね/よ/かな/なんだけど)は SNS・note では正当。無菌の敬体ブログに直しすぎない。
9. **読点は呼吸で打つ。** 音読して息継ぎの位置に打つ。全文に2個ずつ機械的に配らない。人が止まらない助詞の後に足さない。(実測で読者の直覚と統計の両方が一致した唯一の特徴)
10. **新しい段落は新しいものを積む**(事実・動作・例・区別・帰結)。同じ主張の言い換えは前進ではない。
11. **知識は問いが来た場所で出す。** 削っても人物の選択・リスク・判断が変わらない背景段落は、早すぎたか不要。
12. **動作を書いたら感情の解説を追わない。** 「大浴場気持ちよかった、よく寝れた」を「回復装置として機能した」に格上げしない。教訓は一記事に1〜2箇所まで。
13. **書き終わったら止まる。** 「いかがでしたか」も要約のやり直しも未来への飛躍もなし。結びは具体的な事実か自分の判断に戻る。

## 4. 納品前の禁止事項(初稿を書き終えてから照合する)

**「動作」で照合する。字面を変えて同じ動作をしていれば命中。** ただし単発の命中は違反ではなく、密度が判定基準(閾値は下表が唯一の典拠)。

| 禁止 | 閾値 | 備考 |
|---|---|---|
| 記号の残骸:対応の取れない `**`・`: `+半角スペース・全角ダッシュ ──・絵文字の均等撒布 | **ゼロ容認** | コード・リンク・frontmatter・正当な Markdown 強調は免除。── は読点・改行・コロンに置換 |
| 定型句(強表):いかがでしたか/ぜひ〜してみてください/〜に他なりません/解説していきます/近年〜が注目され 等 | **ゼロ容認** | コーパス実測で人間がほぼ書かない語だけを載せた表(§1 強表)。弱シグナル語(さて/このように/不可欠/重要なのは/最後に)は対象外 |
| 反転構文:AではなくBだ/単なるAではなく/Aでもない、Bでもない、Cだ | **長文3回以上・短文1回で疑う** | 実在する誤解の訂正は1回まで正当。直すときは B を直接書く |
| 三点セット:「3つのポイント/観点/原則」 | 見たら疑う | 2つか1つに削れないか。数は先に決めない |
| 壮大化語彙:真理/虚飾/境地/美学/冷徹…(全表 §3) | **一記事2個以上** | 普通の感想は普通の語彙で |
| 段落内ヘッジ:〜可能性がある/〜とは限らない/〜と言えなくもない | **一段落2個以上** | 段落に1つまで。言い切れないなら条件を具体的に書く |
| 命題型H2 + 冒頭の言い換え | 見たら直す | 見出しは名詞句。本文は具体例から |
| 儀式化した免責(節ごとの保険文) | **一記事1箇所まで** | 本当に必要な1箇所だけ残す |
| 横文字メタファー/偏愛語/カタカナ過剰 | §2 §4 の表で個別判定 | 技術文脈の用語は免除。比喩用法だけが slop |
| 文体混交:同段落内の です・ます ↔ だ・である の無意図な切替 | 見たら直す | 引用や内心の声など意図的な降格は免除 |
| 漢語連続:一文に抽象漢語名詞4個以上(「利用促進を図る取り組み」) | 見たら分解 | 和語の動詞文に(「使ってもらいやすくする」)。判定法は §7 |

## 5. 実測にもとづく「逆方向」注意(改稿の前に必ず読む)

計量言語学の実測(大西夢・広島大 2026、Zaitsu & Jin 2023。詳細と適用範囲は `references/evidence-ja.md`)によると、**通説どおりに直すとかえって AI に近づく**修正が3つある。natural-japanese のリズム検出と相補的で、あちらが「測る」、こちらは「逆に捻らない」。

1. **繰り返し語を類義語に置換して「多様性を上げ」ない。** AI の語彙多様性(TTR)はもともと人間より高い。同じ語を繰り返すのは人間の側。機械的な類義語置換は AI 方向への修正。
2. **「人間らしさ」のために比喩を足さない。** 実測で比喩は AI が人間の5倍近く使う。「まるで〜のよう」は AI 頻出。正しい方向はテンプレ比喩(地図/羅針盤/土台/エンジン…)を削ること。
3. **接続詞を一律に削らない。** 硬い文体では使用量に人間と AI の差がほぼ無い。本当の差は**種類**——AI は「一方/しかし/また」の三点セットに偏り、人間は「あるいは/そして/ただ/しかも」も使う。直すなら種類を替える。量は減らさない。

## 6. 検査工程(改稿ループ)

1. **機械検査**(natural-japanese がある場合):

   ```bash
   LINT=""
   for d in ~/.claude/skills/natural-japanese ~/.agents/skills/natural-japanese; do
     [ -f "$d/scripts/lint.py" ] && LINT="$d/scripts/lint.py" && break
   done
   if [ -n "$LINT" ] && command -v uv >/dev/null 2>&1; then
     uv run "$LINT" --json <file> --genre <essay|tech|business> > r1.json   # §0 で判定した文書タイプに合わせる
     # 改稿後: --baseline r1.json を付けて再実行し、出力は別ファイルへ
   fi
   ```

   finding は疑いであって判決ではない。**統計は日本語本文だけで読む**——コードブロック・引用・英語率の高い段落は文長/TTR/固有名詞の統計から除外する。
   **lint が動かないとき**(uv なし・依存の導入失敗):natural-japanese の `references/manual-checklist.md` 相当の観点を人手でなぞり、納品時に「機械検査未実施」と明記する。**空の結果は合格ではない。**
2. **gut-check(finding 1件ごとに必ず通す。精度の生命線)**:(a) この箇所は書き手の実際の声・判断を担っているか。担っているなら「残す(理由)」と記録して手を付けない。(b) 不自然に読めるのはレジスタや題材のせいか(ビジネスの敬語・技術用語)、それとも言い回し自体が機械か。レジスタ由来なら削らない。**この関門を飛ばすと誤検知製造機になる。**
   例外:`low_lexical_diversity_*`(TTR/MTLD)の finding は既定で「残す」——§5 の1番のとおり、類義語置換は逆方向。本当に稚拙に読める繰り返しだけ、文ごと書き直す。
3. **密度の関門**:1件ずつは gut-check を通るのに全体が変なとき → 構造の反復を数える(同型の書き出し ×?、反転構文 ×?、同じ段落長 ×?)。同型3回以上は構造的 slop で、このときは密度が主結論。
4. lint を再実行(`--baseline` 付き)。新しい finding が出なくなるまで 2〜3 を繰り返す。
5. **最後の素読み**(ルールを全部忘れて):どこで書き手が本当に見た人だと信じられるか。どの段落が人の思考で、どの段落がタスクの消化か。素材より大きく言った文はどれか。文章は実際にはどの一文で終わっているか。

## 7. 文体キャリブレーション(任意)

ユーザーが自分の過去原稿を1〜3本くれる場合、書く前に読んで、文長のリズム・判断の下し方・敬体の締め具合・数字の密度を下敷きにする。**複数の文章をまたいで繰り返される個人の癖は「統一性」であり、人間らしさの第三要素**——禁止表に載っていても削らない(gut-check の(a)が優先)。

## 8. 納品

作品だけを渡す。素材リスト・語りの位置の内部回答・判断の記録は見せない。lint の JSON や中間稿は消す。ユーザーのプロファイルを勝手に作らない。
