# ja-human-writing

让日文读起来像「有个人写的」的 Claude Code skill。

v0.1.0 · 2026-08

## 要治的是这种文字

```
近年、デジタル資産の世界は急速な発展を遂げています。しかし、その一方で、
セキュリティに関する課題も浮き彫りになってきていると言えるでしょう。
```

*近年来,数字资产的世界正在飞速发展。但与此同时,可以说安全方面的课题也逐渐浮出水面。*

## 要写成这样

```
7月7日、Gate のあるユーザーの口座から170万ドルが41分で抜かれた。
気づいたのは26時間後。
```

*7 月 7 日,Gate 一个用户的账户在 41 分钟内被抽走 170 万美元。他 26 小时后才发现。*

差别不在词汇。上面那段没有日期、没有金额,而且没有人在做任何事——「课题浮出水面」的主语是课题。读者能读出来:写的人根本没看过这件事。

**删禁用词不会把上面那段变成下面那段。** 缺的是材料,和一个站在具体位置上的说话人。这个 skill 补的就是这一层。

## 它是什么,不是什么

**它不是 NLP 工具,是 prompt 和工作流层。** 检测引擎不是自己写的。

- 机器测得准的部分(句长离散度、禁用词、翻译腔)→ 扔给 [coji/natural-japanese](https://github.com/coji/natural-japanese) 的 lint(机检脚本)
- 禁用词表 → 从 [stop-ai-slop-jp](https://github.com/iKora128/stop-ai-slop-jp) 和 [slop-nuki](https://github.com/chezou/slop-nuki) 搬来重组的,**内容有重叠**(见「跟现有 skill 的关系」)
- **它自己的实体是三样**:动笔前的材料闸、说话位置的设定、以及不把机检结果自动照改、而是一条条判断「这处是不是作者的声音」的循环

## 三个部件

**1. 动笔前的闸**

超过 1200 字的非虚构,开写前先凑齐 5 件带出处的具体材料:日期、金额、专有名词、别人的原话、失败过的事。凑不齐就去查,或者诚实地写短一点——没有材料的长文,再怎么润色也还是水。

**2. 三条「方向反了」的提醒**

去日文 AI 味最流行的三种改法,全都反着使劲。见下节。

**3. 检测和判断分开**

机器出「嫌疑」,**Claude 按 skill 的规则一条条判「改还是留」。** 不需要你自己去判断日文自不自然——最后拍板的是你,但找问题是机器和 Claude 的活。日语不是母语的话,这条尤其重要。

## 三条流行改法,实测是反的

| 常见建议 | 实测 | 正确方向 |
|---|---|---|
| 把重复的词换成同义词 | 词汇多样性(TTR = 用到的词种数 ÷ 总词数)**是 AI 更高**,爱重复的是人类 | 别换。允许重复 |
| 太干了,加点比喻 | 比喻**AI 用得比人类多几倍**,「まるで〜のよう」是 AI 高频 | 别加。删掉模板比喻 |
| 接续词太多,砍掉 | 硬文体里**用量几乎没差**。真差异在种类,AI 只会那三个 | 别减数量,换种类 |

### 证据有多硬(直说)

这三条踩在**两个强度不同的出处**上。

- **同行评审论文**:Zaitsu & Jin 2023, *PLoS One* 18(8), [PMID 37556434](https://pubmed.ncbi.nlm.nih.gov/37556434/)——用机能词使用率等特征判别日文 AI 生成文,谁都能当场查证
- **本科毕业论文**:大西夢『AI生成文からみた「自然な日本語」についての研究』(広島大学文学部 2026)——AI 与人类文本各 20 篇。**20 篇样本的本科卒论,外部不容易验证**

上表里「AI 更高 / 更多」这个**方向**来自卒论。**具体数值没被当阈值用,所以这里不列**(skill 内部也只按方向判断)。数字在 `references/evidence-ja.md` 里带出处写着,但要带着但书读:方向参考,不是普适阈值。

这篇卒论最有用的其实不是数字,是那个框架:把「AI 味」拆成两层——读者能指出来的(特定词汇、读点位置),和读者说不出来但下意识感觉得到的(句长离散度、回避断定的密度)。**实测出差异的几乎全在第二层。**

## 安装

**前提**:装好 [Claude Code](https://claude.com/claude-code)。终端只用这一次。不额外花钱(跑在你现有的 Claude 额度里)。

打开终端,把这三行按顺序粘进去。

```bash
mkdir -p ~/.claude/skills
git clone https://github.com/vincent-wen789/ja-human-writing.git
cp -R ja-human-writing/ja-human-writing ~/.claude/skills/
```

要装机检的话(可选、推荐),再来两行:

```bash
git clone https://github.com/coji/natural-japanese.git
cp -R natural-japanese/skills/natural-japanese ~/.claude/skills/
```

之后不用再碰终端。

<details>
<summary><b>这两行到底在干什么</b></summary>

- `mkdir -p ~/.claude/skills` —— 建好放 skill 的地方(已经有就什么都不做)
- `git clone` —— 把 GitHub 上的一个文件夹下载到你当前所在的位置
- `cp -R ... ~/.claude/skills/` —— 把那个文件夹复制到 Claude Code 找 skill 的地方
- **它只是复制。** 不删东西,不改系统设置。不喜欢就把复制过去的文件夹删掉,一切照旧
- **不需要管理员权限**(全在你自己的用户目录里完成,公司发的电脑通常也能跑)
- **「Claude Code」不是浏览器或桌面 app 里的 Claude**,是跑在终端里的那个,要先装好。费用包含在你的 Claude 订阅里,**这个 skill 本身免费**
</details>

- **机检是可选的。** 不装 natural-japanese,那一步降级成人工清单,skill 照样跑
- 要用机检的话需要 [uv](https://docs.astral.sh/uv/),Python 依赖它自己会装,不用手动 pip
- **skill 指令本身是日文写的**(规则讲的就是日语特有现象),但你用什么语言跟 Claude 说话都不影响
- **Windows**:`cp -R` 换成 PowerShell 的 `Copy-Item -Recurse`

## 怎么用

直接跟 Claude Code 说:

```
你:      这篇 note 草稿,把 AI 味去掉

Claude:  机检报了 7 条,我改其中 3 条。

         L3  「〜と言えるでしょう」→ 改成断定
         L9  每段长度都一样 → 把一段切成两句
         L21 这段没有专有名词也没有数字。
             实际的店名或日期能补上吗?

         剩下 4 条没动。「〜と思う」的重复是你的语气在起作用,留着。
```

其它用法:

- **「写一篇关于 X 的 note 記事」**(note.com,日本的博客平台)——材料闸先跑,材料不够会先反问你,而不是先给你一篇空稿。问题一次问完,最多三个
- **「看下这封邮件的敬语」**——二重敬语、させていただく 滥用、缓冲语连打

## 让它学你的语气(可选)

「按规则改,会不会把我自己的语癖也磨平?」这块是设计里守住的。

给它 1〜3 篇你自己认可的旧稿,它会拿你的句长节奏、下判断的方式、敬体的松紧当基线。而且**跨多篇反复出现的癖好,就算命中禁用表也不删**。人的文体是单篇内有摇摆、跨篇有一贯;AI 恰好相反(单篇内均匀、跨篇没人格)。所以那些反复出现的癖好正是要保的东西。

## 跟现有 skill 的关系

**禁用词表是从 stop-ai-slop-jp 和 slop-nuki 搬来重组的,内容确实重叠。** 这点摆在明面上说,不埋在致谢里。

差分是两条:**动笔前那一层**(材料闸、说话位置),以及**改的方向**——上面三条反转搞反了,你以为在消臭,其实在往 AI 方向拧。

三个都装的话:natural-japanese 只是被当 lint 调用,不冲突;stop-ai-slop-jp 和本 skill 会**重复加载相近的禁用词表**(不矛盾,但吃 context)。**二选一就够。** 如果你已经用熟了 stop-ai-slop-jp、又不在乎动笔前那层,换过来的理由不强。

**context 成本实测**:常驻的只有 description 那几十 token。skill 触发时 `SKILL.md` 本体约 **1 万 token**,`references/` 按需加载(禁令表约 7.7k / 实证层约 3.9k)。装了十几个 skill 的话,按这个数字判断。

## 边界

- **实证基础是意见文和作文的对比,SNS 短文不在里面。** 140–500 字时句长统计会因样本不足而沉默
  - **短文里仍然有效的**:定型句(「いかがでしたか」等)、翻译腔、主语偷换、记号残骸、有没有材料——这些不吃字数
  - **短文里失效的**:句长离散度、段落结构、体言止め占比。skill 会把这些明确标成「不适用」并闭嘴
  - **别把这个沉默读成「没有 AI 味」。** 这部分得自己看
- **底子是意见文、随笔、采访类稿子,技术文章不是靶心。** 材料闸要的「日期、金额、原话、失败过的事」适合带体验或采访的文章;技术解说的材料形态不一样(代码、报错、版本、复现步骤)。禁令表和文体部分照样有效,所以写技术文的话,lint 用 `--genre tech` 跑,材料闸当参考看
- 一个出处是本科卒论(20 篇样本)。如上,只用方向不用数字
- **只验证过 1 个案例**(`examples/`)。那说明流程可复现,不等于效果被证明
- 版本 0.1.0。上游(natural-japanese、stop-ai-slop-jp)更新后的跟进目前是手动的。发现问题欢迎开 Issue
- 作者是住在日本的 marketer([@vinentW789](https://x.com/vinentW789)),不是工程师。这东西出自「自己要写日文发出去」的需求,只要我还在用就会继续修。背后没有公司

## 结构

| 文件 | 内容 |
|---|---|
| `SKILL.md` | 主体。文体判定 → 材料闸 → 说话位置 → 执笔十三条 → 交稿前禁令表 → 检查循环 |
| `references/forbidden-ja.md` | 禁令词表(定型句/AI 偏爱词/夸大语汇/主语偷换/结构/敬语/汉语硬度/记号) |
| `references/evidence-ja.md` | 实证层。两层框架、人味三要素、指标、三条反转 |
| `examples/` | before/after 实文本 + lint 结果,可自己复现 |
